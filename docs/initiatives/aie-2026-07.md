## 4. Core Product Loop

Current loop:

```text
User brain -> guide -> business brain -> Pam challenge -> human approval -> Doc dispatch -> runtime execution -> coaching -> brain improves
```

Plain version:

1. **Build the user brain.** Understand who is sitting in the chair: their AI experience, context skill, technical comfort, commercial judgement, and where they need support.
2. **Pick the guide.** Full Story, Light Story, or No Story.
3. **Build the business brain.** Capture context, rules, goals, examples, edge cases, and what "good" looks like.
4. **Challenge when it matters.** Pam stress-tests important reasoning before action.
5. **Human decides.** The system gives points of view; the person with judgement chooses.
6. **Doc acts.** Approved briefs become records, packages, or implementation jobs.
7. **Runtime executes.** HyperAgent is the first runtime AstraJax services.
8. **Celebrate and coach.** Scorekeeper / Coach Whit style feedback keeps people improving.
9. **The brain learns.** Human feedback improves context over time.

## 5. Agent Roles

Core line:

> **Clive is the face. Pam is the raised eyebrow. Doc is the hands. Humans keep judgement.**

### Clive

Reasoning partner. Helps the user explain the business, context, goals, risks, and agent ideas. Warm, accessible, characterful. Does not write approved system state.

### Pam Portiscue

Challenger. Stress-tests important thinking when the system risks becoming too agreeable, too broad, or too quick to act. Pam does not decide. She gives the sceptical case.

### Human

Judge and approver. The human decides what becomes trusted context, policy, agent configuration, or live action.

Product line:

> **This is your decision. You now have context-aware, bias-checked opinions. You decide.**

### Doc Albright

Action dispatcher. Receives approved briefs and routes them:

- structured records -> direct Airtable/MCP/API write
- build work -> Opus dispatch prompt -> Composer worker
- runtime package -> HyperAgent-ready export

Doc does not re-decide the issue. If the brief is unclear, Doc escalates.

### HyperAgent

Runtime partner. HyperAgent runs **deployed** agents; AstraJax prepares the brain, adoption system, context, guardrails, coaching, and packaging. Build and Airtable amendment work goes through **Composer/Cursor** after Doc proposes and the human approves — not through HyperAgent.

Positioning:

> **HyperAgent makes powerful agents possible. AstraJax makes them adoptable by the teams who know the work.**

## 6. Architecture Decisions Already Made

### User Brain

Before building a business brain, AstraJax maps the user:

- AI usage and prompting
- context environments
- system architecture
- coding comfort
- commercial forecasting / judgement
- data quality and evidence
- team leadership and change

This controls how Clive explains, where Pam challenges, and how much support the system offers.

### Business Brain

Each themed area has a brain: a set of approved context records.

The main business brain contains short summaries and vital business context.

Agents receive:

```text
Rules
+ Skills
+ Main Brain
+ Skin Brain
+ current task/user context
```

Agents should only widen into other brains when evidence is insufficient, not because the model "feels" uncertain.

Better phrase:

> **Agents can widen context only when the approved evidence they already have is not enough.**

### Skin Brain

Skin Brain is behavioural, not factual.

It can contain:

- persona
- tone
- dialogue style
- role boundaries
- allowed behaviours
- forbidden behaviours

It should not contain important business truth.

### Brain Maturity

Brains have maturity levels. Maturity controls answer authority.

Example levels:

```text
Seedling Brain
House-Trained Brain
Working Brain
Sharp Brain
Trusted Brain
Elder Brain
```

Maturity is earned through human QA, management sign-off, stale-context cleanup, low contradiction rate, and real answer quality.

Key rule:

> **Brain maturity is earned by human review, not agent confidence.**

### Brain Efficiency Credit

In production, better brains should cost less to run.

Commercial principle:

> **AstraJax rewards context quality because better context makes AI cheaper, safer, and more useful.**

The discount should usually apply to usage / overage, not the base platform fee.

> **AstraJax runs on the same pattern it sells. Domain experts keep judgement. AI agents take action from approved briefs. Creative specialists make the system human enough to adopt.**

Operating model:

- Matthew owns human-centred product, commercial direction, and story architecture.
- Cursor is Doc for founder build work: approved brief -> code/docs/demo assets.

- AI surrounds high-judgement humans with leverage; it does not replace the judgement that makes their work valuable.

Important point:

> **The system gives intelligent points of view. The human decides.**

This applies to product and company operations.
